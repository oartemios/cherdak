# Чердак

Личный архив историй и игровых миров. Чердак собирает проекты из обычных папок и открывает их в браузере. В нём можно читать и редактировать Markdown, искать по текстам, оставлять заметки и слушать озвучку глав.

- **Каталог.** Книги и игры хранятся в двух папках. Каждый вложенный каталог верхнего уровня становится отдельным проектом. Проекты можно помечать тегами и показывать карточками или таблицей.
- **Чтение и заметки.** Внутри проекта доступны дерево файлов, оглавление страницы, ссылки `[[название]]`, заметки к выделенному тексту и просмотр PNG и холстов `.canvas`.
- **Озвучка.** Можно прослушать выделенный текст, подготовить аудио всей страницы и перегенерировать отдельный фрагмент с исправленным произношением. Локальные и облачные голоса подключаются по желанию.

## Быстрый старт

Понадобятся **Python 3.9 или новее** и браузер. Сервер и каталог работают на стандартной библиотеке Python. Для первого запуска не нужны модели, ключи API или сборка фронтенда.

```sh
git clone https://github.com/oartemios/cherdak.git
cd cherdak
cp config.example.json config.local.json
```

Укажите в `config.local.json` пути `books_root` и `games_root` к двум **существующим папкам**. Неиспользуемую папку можно оставить пустой. Например:

```text
cherdak-library/
├── books/
│   └── Первая история/
│       └── Глава 1.md
└── games/
```

Если этот каталог находится в домашней папке, задайте `"books_root": "~/cherdak-library/books"` и `"games_root": "~/cherdak-library/games"`. Существующие проекты можно подключить на месте. Пути с `~` отсчитываются от домашней папки, относительные пути — от папки Чердака.

```sh
python3 server.py
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). Выберите проект и откройте Markdown-файл. Сервер слушает только локальный интерфейс. Чтобы остановить его, нажмите `Ctrl+C`.

## Разметка Markdown

Чердак поддерживает синтаксис CommonMark, таблицы, зачёркивание и списки задач. Относительные ссылки на файлы проекта открываются в каталоге, а PNG можно вставить в текст через `![Описание](images/map.png)`. Ссылки Obsidian вида `[[Глава|Название]]` также работают.

Чтобы выделить заметку, совет или предупреждение, добавьте маркер в начало цитаты. Заголовок после маркера можно опустить.

```markdown
> [!TIP] Перед публикацией
> Проверьте имена персонажей и ссылки на главы.
```

Доступны маркеры `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]` и `[!CAUTION]`.

## Озвучка

Откройте Markdown-файл и выберите **«Озвучивание»** в боковой панели. Выберите режим и нажмите **«Подготовить аудио»**. Чтобы попробовать голос на коротком отрывке, выделите текст и нажмите **«Прослушать выделенное»**. Генерация страницы идёт в фоне, пока работает сервер.

| Режим | Что понадобится |
| --- | --- |
| **Локальные голоса** | Piper и хотя бы один из русских голосов: Руслан, Ирина или Дмитрий. |
| **Мои голоса** | Qwen3-TTS Base через MLX на Mac с Apple Silicon. Для нового профиля запишите голос или загрузите WAV PCM длительностью 2–60 секунд и укажите текст записи. |
| **VoiceDesign** | Qwen3-TTS VoiceDesign и Base через MLX. Выберите тип голоса и примерный возраст. После готовности первого фрагмента эталон можно сохранить и выбирать на других страницах в «Моих голосах». |
| **OpenAI** | Интернет и ключ API. В этом режиме текст передаётся в OpenAI, а запросы могут тарифицироваться. |

Чтобы исправить произношение, откройте **«Настройки и действия» → «Редактировать фрагменты»**, выберите фрагмент и нажмите **«Перегенерировать»**. В тексте для озвучки можно поставить знак ударения, например `замо́к`. Модель может по-разному реагировать на подсказку. Правка относится только к аудио выбранного фрагмента.

### Локальные голоса Piper

Пример установки с Python 3.12 и версией Piper, использованной в проекте. Выполните из корня репозитория:

```sh
python3.12 -m venv .piper-env
.piper-env/bin/python -m pip install 'piper-tts==1.8.0'
mkdir -p voices
.piper-env/bin/python -m piper.download_voices --download-dir voices ru_RU-ruslan-medium
```

Чтобы включить Ирину или Дмитрия, повторите последнюю команду с `ru_RU-irina-medium` или `ru_RU-dmitri-medium`. Файлы `.onnx` и соответствующие `.onnx.json` должны лежать рядом. Источник — [русские голоса Piper](https://huggingface.co/rhasspy/piper-voices/tree/main/ru/ru_RU).

### Свои голоса и VoiceDesign на Apple Silicon

Проверенная конфигурация — Mac M1 с 16 ГБ, Python 3.12 и MLX Audio 0.6.5. Скачайте [Qwen3-TTS Base 0.6B 8-bit](https://huggingface.co/mlx-community/Qwen3-TTS-12Hz-0.6B-Base-8bit):

```sh
python3.12 -m venv .clone-env
.clone-env/bin/python -m pip install 'mlx-audio==0.6.5' 'huggingface_hub[hf_xet]'
.clone-env/bin/hf download mlx-community/Qwen3-TTS-12Hz-0.6B-Base-8bit --local-dir models/qwen3-tts-0.6b
```

Для VoiceDesign дополнительно скачайте [Qwen3-TTS VoiceDesign 1.7B 8-bit](https://huggingface.co/mlx-community/Qwen3-TTS-12Hz-1.7B-VoiceDesign-8bit) в путь, который ожидает приложение:

```sh
.clone-env/bin/hf download mlx-community/Qwen3-TTS-12Hz-1.7B-VoiceDesign-8bit --local-dir models/qwen3-tts-1.7b-voicedesign
```

VoiceDesign — экспериментальный режим. Первая реплика создаётся по описанию, следующие озвучиваются через Base с первой репликой в качестве образца. Тип и возраст служат ориентирами, а тембр и интонация могут варьироваться.

Расшифровку образца можно ввести вручную. Для кнопки **«Распознать текст»** скачайте [Qwen3-ASR 0.6B 8-bit](https://huggingface.co/mlx-community/Qwen3-ASR-0.6B-8bit) и задайте `"qwen_asr_model": "models/qwen3-asr-0.6b"` в `config.local.json`.

```sh
.clone-env/bin/hf download mlx-community/Qwen3-ASR-0.6B-8bit --local-dir models/qwen3-asr-0.6b
```

### OpenAI

Перед запуском сервера задайте `OPENAI_API_KEY` в его окружении. Имя модели настраивается через `openai_model` в `config.local.json`. Локальные модели для этого режима не требуются.

## Настройки и данные

Пути к проектам, интерпретаторы движков, тайм-ауты и порт можно изменить на странице **«Настройки»** или в [локальной конфигурации по примеру](config.example.json). После изменения серверных параметров перезапустите сервер. Настройки вида хранятся в браузере и применяются сразу.

Markdown редактируется непосредственно в файлах проекта. Заметки и теги хранятся отдельно в `.notes.sqlite3` и `tags.json`, профили голосов — в `.voice-profiles/` и `.voice-sample/`, задания и аудио — в `.speech-jobs/` и `.speech-cache/`. Заметки, голоса, локальная конфигурация и скачанные модели исключены из Git. При переезде сделайте резервную копию этих данных. Виртуальные окружения после переноса папки может потребоваться создать заново.

При перезапуске сервера общая очередь озвучки восстанавливается. Прерванную перегенерацию одного фрагмента нужно запустить повторно. Если озвучка не запускается, проверьте пути к интерпретатору и весам выбранного движка в настройках.

## Разработка

```sh
python3 dev_server.py
python3 -m unittest discover -s tests
node --test tests/*.mjs
```

Dev-сервер перезапускается после правок серверных Python-файлов и `config.local.json`. После правок HTML, CSS или JavaScript обновите страницу. Тесты не требуют моделей и ключей API. Для HTTP-тестов нужен доступ к локальным сокетам.

Исходники интерфейса находятся в `web/`, точка входа сервера — `server.py`, модули озвучки — в `speech_*.py`. Крупные изменения проходят через отдельную ветку и PR. См. [правила проекта](AGENTS.md), [план рефакторинга](REFACTORING.md) и [результаты экспериментов с озвучкой](reports/speech-experiments.md).
